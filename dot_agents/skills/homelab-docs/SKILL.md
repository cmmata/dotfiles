# Homelab docs

The user's personal documentation repository lives at **`$HOME/dev/docs`** (git repo, "Appsinet docs" — single source of truth for homelab and client infrastructure).

## First step

Always read **`$HOME/dev/docs/AGENTS.md`** and **`$HOME/dev/docs/README.md`** before working in the repo. They define the layout and the non-negotiable rules; the summary below is only a shortcut.

## Layout

```
README.md            human entry point / index
AGENTS.md            rules every agent must follow in this repo
decisions/           one file per architecture/naming/tooling decision
projects/            one file per active or finished plan
homelab/
  servers/           one page per server (hardware, services running on it)
  services/          one page per service + optional <service>/ config folder
  network/           network map, IP ranges, VLANs, DNS records, port map
clients/             one folder per client, same shape as homelab/
howtos/              step-by-step guides, named howto-<topic>.md
templates/           page templates to copy: service.md, server.md
generated/           compiled by CI from infra/k8s — DO NOT hand-edit
scripts/             helper scripts run by CI (.github/workflows link check)
```

Section `README.md` files are indexes — check them to find the right page, then link new pages from the index when you add one.

## Finding things

- Search with ripgrep from anywhere: `rg -n "<query>" ~/dev/docs` (add `-l` for file list, `--glob 'homelab/**'` to scope).
- Read pages with `read_file` on the absolute path under `~/dev/docs`.
- "What runs on server X?" → `homelab/servers/<x>.md` and `homelab/services/`.
- "How do I X?" → `rg -n "X" ~/dev/docs/howtos`.
- "Why did we choose Y?" → `rg -n "Y" ~/dev/docs/decisions`.

## Non-negotiable rules (from the repo's AGENTS.md)

1. **No secrets, ever.** No passwords, API keys, tokens, or private keys in docs. Reference the password manager entry instead, e.g. `vault: infra/pihole`.
2. **`generated/` is compiled.** Regenerated by CI; never hand-edit it. If stale, fix the generator or flag it.
3. **No infra change without docs.** Any change affecting a service, host, IP, port, version, or dependency must produce a docs update in the same task, before reporting done.
4. **Docs match reality.** If docs contradict the infra repos, fix the docs or open an issue. The related repos are `~/dev/homelab/homelab-iac` (OpenTofu + Ansible) and `~/dev/homelab/k8s-gitops` (Flux manifests) — when they are available locally, verify facts (IPs, versions, ports, workloads) there instead of trusting memory.

## Creating or updating pages

- One topic per file. How-tos are named `howto-<topic>.md` in `howtos/`.
- New service or server pages: copy `templates/service.md` or `templates/server.md` and keep its shape (fields table with Host / IP / Port(s) / Version / Source, then Purpose, Dependencies, Notes).
- Decision files keep the shape: context, options considered, final decision — and link the pages they affect.
- Link every new page from the relevant section `README.md` index.

## Committing in the docs repo

- `docs: <topic>` — normal documentation update.
- `docs: update <service> after <change>` — after an infra/k8s change; cross-reference the related repo's PR/commit in the body.
- `docs-chore: <topic>` — layout, templates, tooling.

CI runs a Markdown link check on PRs (`scripts/check-links.py`), so keep relative links valid.
